# **ESL app: Lightner Box \+ RAG — Project Plan**

## **1\. Executive Summary**

This document defines the project plan for a vocabulary-building ESL app that combines the Lightner Box method with Retrieval-Augmented Generation (RAG) and an on-device local language model (e.g., Gemma 3:4b). The goal is to help learners develop usable vocabulary — not just translations — by teaching morphology, derivations, part-of-speech family, collocations, and contextualized sentence use.

## **2\. Learning Principles**

1. Lightner Box (Spaced Exposure \+ Prioritization):

   * Prioritize unknown and partially-known words by frequency and learner performance.

   * Use graduated exposure: reintroduce words at increasing intervals until mastery.

2. Contextualized Learning:

   * Teach words in sentences and short discourse to establish typical pattern and collocations.

3. Morphological Awareness:

   * Present derivations (verb \-\> noun \-\> adjective \-\> adverb) and common morphological patterns.

4. Productive Usage:

   * Include generative production tasks: fill-in-the-gap, sentence rephrasing, short speaking/writing prompts.

5. RAG and Local LLM for Personalization:

   * Use RAG to pull relevant examples from a curated knowledge base (news, graded readers, corpora) and augment with locally generated examples from Gemma3:4b.

## **3\. Target Users and Levels**

1. Primary: A2–B1 ESL learners (pre-intermediate to intermediate)

2. Secondary: B2 learners needing systematic coverage of high-frequency gaps

3. Device and connectivity assumptions:

   * App should work offline for core practice using local LLM; RAG features will use a local document store and optional server sync.

## **4\. Core Features (MVP)**

1. Lightner Box scheduler and dashboard

2. Word card view: lemma, frequency rank, POS, definitions, Chinese translation (zh-TW optional), morphology family

3. Context generation: 5 example sentences per target word (sourced via RAG from local corpus \+ generated by local LLM)

4. Production tasks: gap-fill, sentence rewriting, short answer prompts, multiple-choice with plausible distractors

5. Automatic morphological drill: present verb forms (base, 3rd s, \-ing, past, past participle), noun forms, adjective/adverb forms

6. Assessment module: micro-tests per session and milestone tests to verify mastery

7. Progress tracking: mastery status per word (Unknown, Learning, Practiced, Mastered) and metrics

8. Admin/Authoring tools: teacher can add word lists, corpora, and tags; export/import

## **5\. Data Model**

1. Word entity: lemma, POS, frequency\_rank, definitions\[\], translations\[\], senses\[\], example\_sentences\[\], morphology\[\], collocations\[\], tags\[\], last\_seen, easiness\_score

2. User\_word\_state: user\_id, word\_id, status, review\_history\[\], response\_times\[\], error\_types\[\]

3. Corpus/Knowledge Base: documents with metadata (source, grade-level, date, topics)

4. RAG index: vector store with document chunks and metadata; local-only by default with optional server sync

## **6\. AI Integration and RAG Flow**

1. Local LLM: Gemma3:4b runs on-device (or local server) to generate contextual example sentences and plausible distractors.

2. RAG pipeline:

   * Query index with the target word and learner context (level, recent mistakes).

   * Retrieve top-k document passages that show natural uses and collocations.

   * Synthesize examples: the system combines retrieved sentences and LLM to produce 5 curated examples per word: 2 retrieved as-is (or simplified), 3 generated by LLM adapted to learner level.

3. Quality:

   * Use filters to remove idioms that are too advanced.

   * Ensure generation stays within A2–B1 vocabulary or flagged for teacher review.

## **7\. Learning Tasks and Task Types**

1. Recognition tasks: multiple-choice, true/false

2. Comprehension tasks: matching definitions to sentences

3. Production tasks: fill-in-the-blanks, sentence completion, short answer

4. Morphology drills: generate noun/verb/adjective forms; select correct form in context

5. Collocation tasks: choose best collocation in a sentence

6. Spaced recall sessions: Lightner box reviews with adaptive intervals

7. Milestone tests: cumulative mastery tests (see Section 9\)

## **8\. Metrics and Mastery Criteria**

1. Word-level mastery criteria (suggested):

   * Recognition: 4/5 correct in two separate sessions

   * Production: correctly use the word in a controlled sentence twice within one week

   * Morphology: correctly produce 3 derived forms in two attempts

   * Collocations: select correct collocation in 3/4 questions

   * If all conditions met, mark as Mastered; otherwise remain Learning/Practiced.

2. System metrics:

   * Retention rate at 1 day, 7 days, 30 days

   * Average response time per item

   * Error type distribution (meaning confuse, form confuse, collocation confuse)

## **9\. Milestones and Tests for Development Progress**

1. Phase 0 — Project Setup

   * Task 0.1: Define tech stack, storage, and model deployment plan. Test: architecture diagram and PoC runbook.

   * Task 0.2: Prepare initial corpus (graded readers, example sentences). Test: corpus ingest script and sample vector index.

2. Phase 1 — MVP (core features)

   * Task 1.1: Implement user accounts and basic UI (word card \+ Lightner box scheduler). Test: demo user can add words and perform reviews.

   * Task 1.2: Local LLM integration for generation. Test: on-device generation of 5 sentences per word with basic quality checks.

   * Task 1.3: RAG retrieval pipeline. Test: retrieval \+ generation combo returns mixed items; sample QA process.

   * Task 1.4: Basic production tasks and scoring engine. Test: auto-scoring works for MCQ and exact-matching fill-in; teacher review flow for short answers.

   * Task 1.5: Progress tracking UI. Test: report shows word counts by status and retention metrics for sample users.

3. Phase 2 — Pedagogical Enhancements

   * Task 2.1: Morphology module and derivation drills. Test: module suggests derivations and auto-generates prompts.

   * Task 2.2: Collocation detection and practice. Test: collocation extraction pipeline with precision metrics on sample set.

   * Task 2.3: Adaptive scheduling tuning. Test: compare retention for default vs tuned scheduler on pilot group.

4. Phase 3 — Authoring & Teacher Tools

   * Task 3.1: Teacher list creation, tagging, and bulk import/export. Test: teacher creates a lesson and shares with 5 students.

   * Task 3.2: Review queue for problematic generated examples. Test: teacher can edit and re-publish corrected items.

5. Phase 4 — Scale & Offline

   * Task 4.1: Optimize on-device LLM performance and caching. Test: benchmark generation latency and memory use.

   * Task 4.2: Data sync and privacy compliance. Test: end-to-end sync with encrypted backups and opt-out.

For each task include acceptance tests and CI checks, e.g., unit tests for scheduler math, integration test for RAG pipeline, human spot-check of generated sentences.

## **10\. Sprint Planning and Timeline (suggested)**

1. Sprint 0 (2 weeks): Project setup, corpus ingest, architecture PoC.

2. Sprint 1 (4 weeks): MVP UI, user flows, Lightner box core.

3. Sprint 2 (4 weeks): LLM generation \+ RAG integration, basic tasks.

4. Sprint 3 (4 weeks): Morphology module, production tasks scoring, tests.

5. Sprint 4 (4 weeks): Teacher tools, authoring and review.

6. Sprint 5 (3 weeks): Offline optimization, privacy, pilot deployment.

## **11\. Acceptance Tests and User Tests**

1. Dev acceptance: unit tests, CI pipeline, code reviews.

2. Pedagogical QA: teachers evaluate 200 generated examples for appropriateness and difficulty.

3. Pilot study: 30 learners for 6 weeks; measure retention and transfer (use pre-test/post-test where transfer tasks require using words in new sentences).

4. Usability tests: 10 teachers and 20 learners walk through lesson creation and review.

## **12\. Tech Stack Recommendations**

1. Frontend: React (web) \+ PWA support for offline; mobile wrappers if needed.

2. Backend: Node.js or Go for sync and user management; SQLite for local storage; vector DB (Weaviate, Milvus, or simple FAISS-like local index).

3. LLM: Gemma3:4b local runtime; fallback small transformer for low-memory devices.

4. RAG: Vectorization using sentence transformers; chunking & metadata tagging.

5. CI: GitHub Actions; testing harness for AI outputs.

## **13\. Privacy and Compliance**

1. By default keep user data local. Optional server sync is end-to-end encrypted.

2. Allow teachers and institutions to host on-prem or cloud.

3. Provide export and delete options per GDPR-style rules.

## **14\. Risks and Mitigations**

1. Generation quality: mitigate with teacher review and filtering pipeline.

2. Device constraints for LLM: provide light-weight fallback models and server-assisted generation.

3. Pedagogical drift: maintain human-in-the-loop review and A/B testing.
