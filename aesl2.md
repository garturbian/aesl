# **ESL Vocabulary Builder (Lightner Box \+ Local Generation)**

## **1\. Project Vision**

This is a **single-user local ESL vocabulary trainer** designed for personal or teacher-managed use. It integrates the Lightner Box method for spaced review, a SQLite3 database for progress tracking, and a local language model (Gemma3:4b via Ollama) for generating contextual examples and morphology variations. The app runs entirely offline, without external APIs or data connections.

## **2\. Key Design Principles**

1: Local-first design — all data, models, and reviews stored on-device.  
 2: Structured repetition using Lightner Box intervals.  
 3: Contextual learning via automatically generated examples.  
 4: Morphological awareness — each base word connects to its noun, verb, adjective, and adverb forms.  
 5: Flexible word entry — teacher or learner can add manually, or system can extract from texts.  
 6: Single-user deployment — no group distribution or online sync.

## **3\. Core Data Sources**

1: **Base word list** — 2800 most common English words (ranked by frequency).  
 2: **Local corpus** — optional text files containing graded readers, stories, or previous lessons.  
 3: **SQLite3 database** — tracks user progress, review intervals, and performance.  
 4: **Gemma3:4b model** — generates examples, contextual uses, and derivative forms.

## **4\. Revised RAG Definition (Local Retrieval)**

RAG here refers to local retrieval-augmented prompting. The system retrieves information from local files (e.g., word list, example corpus, review data) and combines it with automatic prompting to Gemma3:4b. It does not query any external API or server. Retrieval is updated automatically as the learner progresses.

Example flow:

* User selects a word or reaches a review prompt.

* System retrieves prior examples and notes from local corpus or previous sessions.

* Prompts Gemma3:4b to generate new, level-appropriate examples, morphology, and collocations.

* Stores results locally for later reuse.

## **5\. Lightner Box Scheduler and Database Structure**

SQLite3 will manage spaced repetition and learner state. Core tables include:

Table: words

* word\_id (PK)

* lemma

* pos

* frequency\_rank

* definition

* translation

* morphology (JSON)

Table: reviews

* review\_id (PK)

* word\_id (FK)

* interval\_days

* last\_review\_date

* next\_review\_date

* easiness\_score

* correct\_count

* wrong\_count

Table: examples

* example\_id (PK)

* word\_id (FK)

* sentence

* source (retrieved | generated)

* date\_created

Table: user\_settings

* preferred\_language

* review\_mode (manual | auto)

* last\_sync

## **6\. Core Functional Flow**

1: Initialize database and load base 2800-word list.  
 2: For each word, the system stores definition, translation, and morphological data.  
 3: When a learner reviews a word:

* Retrieve examples from the local database.

* If examples \< 5, auto-generate new ones with Gemma3:4b.

* Update review data and schedule next review using Lightner algorithm.  
   4: Learner can add new words manually or extract from a loaded text file.  
   5: User dashboard displays review queue, mastered count, and intervals.

## **7\. Learning Process**

1: Review phase (Lightner scheduling)  
 2: Recognition test — choose correct meaning or form  
 3: Morphology test — generate or identify derived forms  
 4: Production test — write or complete a short sentence  
 5: Example generation — use Gemma3:4b to generate contextual sentences showing correct word use  
 6: Database update — mark word as Known, Learning, or Mastered

## **8\. Technical Architecture**

1: **Frontend:** Local web interface (React or lightweight HTML+JS)  
 2: **Backend:** Python or Node.js local server handling database operations and LLM prompts  
 3: **Database:** SQLite3 (single file)  
 4: **Local LLM runtime:** Ollama with Gemma3:4b model  
 5: **Storage:** Local folder structure for user data, logs, and example cache
